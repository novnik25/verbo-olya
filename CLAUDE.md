# Verbo — правила работы над проектом

Windows-приложение: голосовой ввод в любое поле, перевод выделенного текста,
чтение вслух, распознавание текста с картинки и с области экрана.
Автор — один человек, пользователи — он и его друзья. Интерфейс только русский.

## Правила проекта

- **Весь текст для пользователя — по-русски и без жаргона.** Нельзя показывать
  «API-ключ», «Groq», «Whisper», «LLM», «SSML», английские ответы сервисов.
  Техническая подробность идёт в журнал, человеку — понятная фраза.
- **Иконки только SVG,** никаких эмодзи в интерфейсе.
- **Комментарии в коде и сообщения коммитов — по-русски, и объясняют ПОЧЕМУ,**
  а не что. Хороший комментарий описывает грабли, на которые уже наступили.
- **НЕ менять** папку данных `%AppData%\VoxFlow` и `appId com.voxflow.app` —
  потеряются настройки, история и ключ пользователя.
- `build/installer.nsh` — только UTF-8 **с BOM**, `Var` объявлять внутри макроса.
- `core/` не знает про Electron — тем и ценен, что тестируется без него.
  Обвязку Electron туда не тащить.

## Как проверять работу (это важнее тестов)

Тесты обязательны, но их мало. Почти все настоящие ошибки этого проекта
находились **живым прогоном**, а не тестами: пропажа текста при чтении вслух,
обрыв синтеза на амперсанде, ложная карточка «вставить некуда», враньё в
настройках про темп речи. Поэтому:

- запускать приложение и **смотреть на результат** — скриншотами окон,
  реальными файлами, записями в журнале;
- перед релизом прогонять собранный установщик, а не только `npm run build`;
- для панели есть сравнение снимков **до байта** — им проверяется, что правка
  ничего не сдвинула;
- если что-то «не воспроизводится» — сначала снять скриншот экрана: там может
  висеть окно антивируса.

## Сборка и релиз

```
npx tsc --noEmit          # типы
npm test                  # 337 тестов, идут последовательно (см. ниже почему)
npm run dist              # установщик в dist-installer/
```

Дальше: поднять версию в `package.json` → коммит → тег `vX.Y.Z` →
`git push origin master` и `git push origin vX.Y.Z` →
`gh release create vX.Y.Z dist-installer/Verbo-Setup-X.Y.Z.exe --repo novnik25/voxflow-releases --title "Verbo X.Y.Z" --notes-file <файл>`
→ копия установщика в папку OneDrive → `npm run sync` (зеркало кода).

**Заметки к релизу пишутся для человека, а не для разработчика:** что
изменилось в его работе, без имён библиотек и внутренностей.

## Особенности этой машины (иначе потеряете часы)

- **`ELECTRON_RUN_AS_NODE=1` протекает из VS Code** в любой дочерний процесс.
  Electron тогда выполняет приложение как обычный скрипт Node, `require('electron')`
  возвращает строку с путём, и падает `Cannot read properties of undefined
  (reading 'requestSingleInstanceLock')`. Выглядит как поломка приложения, но это
  окружение. **Снимать переменную перед каждым запуском.**
- **Антивирус 360 Total Security** мешает постоянно: прогон тестов падает с
  `spawn EPERM` (потому `npm test` идёт с `--no-file-parallelism`), сборка роняет
  `EPERM` при переименовании `win-unpacked`, а упакованное приложение **зависает
  на старте** на диалоге «защита реестра», если пишется ключ автозапуска.
- **Замок единственного экземпляра:** пока у пользователя запущен Verbo, второй
  экземпляр молча выходит. Перед прогоном закрывать, после — возвращать.
- Изолировать тестовый запуск подменой `APPDATA` **нельзя**: Electron берёт путь
  через Win32 `SHGetKnownFolderPath`. Трогаете настоящие настройки — делайте
  резервную копию и сверяйте хеш после восстановления.
- `.ps1` без BOM PowerShell 5.1 читает как ANSI — кириллица внутри ломает разбор.
  Держите скрипты на латинице либо пишите с BOM.

## Что сознательно не сделано

`src/renderer/src/overlay.tsx` — функция `Overlay` на ~560 строк, внутри пять
независимых экранов. Разбор откладывался осознанно: максимум риска на самой
заметной поверхности при нулевой пользе для человека. Возвращаться к этому,
только когда правка в оверлее реально станет мучительной.

`README.md` устарел: описывает старое имя VoxFlow и не знает про перевод,
чтение вслух и распознавание с картинки.
